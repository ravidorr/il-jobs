# misra - Agent Guide

Canonical instructions for AI coding agents. `CLAUDE.md` and `GEMINI.md` point here; edit this file only.

## Project

Daily batch pipeline that crawls career pages, keeps history in SQLite, and emails a digest. Runs on GitHub Actions; there is no server, API, or UI of its own.

## Commands

- Install: `npm ci`, then `python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'`
- Lint: `npm run lint` (ruff, ESLint, Stylelint, html-validate, markdownlint)
- Typecheck: `npm run typecheck` (mypy, strict)
- Test: `npm run test`
- Coverage: `npm run test:coverage` (pytest, 100% line and branch coverage; mandatory on push and in CI)
- Run the pipeline: `python run.py`, then `python send_email.py` and `python build_dashboard.py` (see README)

## Rules

- Never commit with `--no-verify`. Fix the cause when a hook fails.
- This repository uses GitHub issues for ticketing.
- Linters are strict (ruff, mypy, ESLint, Stylelint, html-validate, markdownlint). Do not weaken rules to pass.
- There is no UI. `/design-system` is a placeholder (see `design-system/README.md`). `docs/index.html` is generated by `build_dashboard.py` from `templates/dashboard.html`: edit the template, never the output.
- Python lives at the repository root (flat modules). Node is dev tooling only (linters, hooks); pin it via `.nvmrc`, package manager is `npm`. Keep `package-lock.json` committed.
- The version of record is `package.json`. PRs that change `package.json`, `pyproject.toml`, or a Python module update `CHANGELOG.md` and bump the version (one SemVer bump per PR). Docs-only, test-only, and workflow-only PRs do not.
- The daily workflow commits `data/jobs.db` and `docs/index.html` straight to `main` as `github-actions[bot]`. The `main` ruleset lets that bot bypass; do not change that flow without updating the ruleset.
- Track open work in `TODO.md`.

## Layout

- Python modules at the root (`run.py`, `adapters.py`, `browser_crawl.py`, `digest.py`, `send_email.py`, `build_dashboard.py`, `discover.py`, `common.py`, dev tools `survey*.py`), `tests/` for pytest
- `data/` - seed lists and the SQLite history; `templates/` - dashboard template; `docs/` - generated dashboard (GitHub Pages)
- `design-system/` - placeholder (no UI)
- `.husky/` - git hooks (pre-commit fast, pre-push broad)
- `.github/` - CI, release, dependabot, templates
